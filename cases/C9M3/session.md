## 缺陷一：分类维度错位——你按“场景”切分，但记忆本身不带场景属性（最根本的缺陷）

你的三条边界是“在工程环境下 / 在日常生活和简单工作中”，即按**使用场景**划分。但一条记忆在写入时并不知道自己会被用在哪个场景：

- “用户讨厌冗长注释”——这是生活偏好还是工作约束？
- “用户妹妹叫小红”——纯生活信息，但用户可能在让我写小说时用到；
- “用户在做的项目用 Rust”——工作信息，但聊天闲聊时也可能提到。

## 缺陷二：混合层是伪解，会退化成“垃圾桶”

每当一个分类体系需要“两者皆有/其他”这样的第三桶，就说明**第一维度切分不干净（不满足 MECE）**。更糟的是：

- 现实中大量记忆天然是跨域的，混合层会不断膨胀，最终变成“没有分层的杂物间”，等于把原问题换了个名字重新引入；
- 用户从来没有第三种“混合需求”——你定义的两个层对应两种真实的用户诉求（jobs to be done），而混合层**没有独立的诉求**，它只是分类失败的补丁。

## 缺陷三：回避了记忆系统真正难的四个问题

你的框架回答的是“记忆放哪个格子里”，但记忆系统的危机不在格子上，而在：

1. **冲突与更新**：用户换了工作、技术栈从 TS 改成 Rust，旧记忆谁负责覆盖？三层都没有“改写裁决”机制；
2. **信任与置信**：工作层约束可被验证（lint 通过、编译成功），生活层了解无法验证——两种记忆的**写入置信机制完全不同**，框架未体现；
3. **时效与衰减**：生活信息会过时（搬了家、分手了），工作约束会失效（项目结束），三层都没有遗忘策略；
4. **调用与调度**：生活层记的东西要不要进入工作会话？如果跨层可调用，层就只是标签；如果不可，记忆系统就废了一半。

## 缺陷四：漏掉了真正该分层的轴——敏感性，而非主题

生活层的本质属性不是“内容关于生活”，而是**隐私敏感、不可外泄**（个人健康、人脉、情绪）；工作层的本质属性是**合规与可审计**（企业数据不能跨会话污染）。权限模型、用户“被遗忘权”的清除范围、跨层泄露事故的防线——这些真正需要分层的维度，你的三层都没有承载。

## 缺陷五：工作层内部结构缺失，目标立不住

你给工作层的任务是“保证超长程任务一致性”，但一致性依赖两种记忆：

- **约束/风格记忆**（规则类）✓ 你的框架有；
- **任务态记忆**（“项目进行到哪、上次改了什么、卡在哪”）✗ 你的框架没有。

只装规则不装进度，“超长程一致性”这个目标本身就不成立。**工作层需要再裂变出“项目/任务态”子层**。

## 缺陷六：对用户的心智负担与产品形态悬空

- 用户能理解并正确选择“三种模式”吗？大概率不能，最终还得系统自动路由——那“三层”就退化成内部实现细节，用户感知回到“一个记忆开关”；
- 每条记忆写入前都要做一次层归属判定，**判定错误 = 静默丢失或跨层污染**，且错误无感、难回滚。

## 缺陷七（对照视角）：重复发明了已有更稳的切分

认知科学里的记忆分类恰好更贴你的诉求：**程序性记忆**（规则、风格、约束——对应你的工作层）与**语义记忆**（关于用户的事实——对应你的生活层），二者**正交**，不存在混合问题。你按场景切是表层现象，按记忆类型切才是结构本质——混合层在后者里自然消失。

## 先说真正的进步

**“外层给用户切模式，内层按性质存储”**——这解决了我上次指出的最根本缺陷（分类维度错位）。记忆不再被迫归档到某个场景格子，而是：

## 但新框架仍有五个缺陷

### 缺陷一：内层三分类不在同一个轴上，且漏掉了最大类

“硬约束、软约束、临时”是**两个不同维度被压扁成三个桶**：

| 分类 | 实际所在轴 |
|---|---|
| 硬约束 / 软约束 | **强度轴**（规则刚性、置信度） |
| 临时 | **时间轴**（是否过期） |

“临时的硬约束”（本项目内必须用 TS，项目结束失效）、“长期的软约束”（一贯偏好深色主题）都真实存在——你的三桶无法安放它们的组合。

更致命的是：**“事实型记忆”在你的内层没有家**。“用户妹妹叫小红”“用户有糖尿病”——这不是约束（不指导任何行为规则），是对用户的静态了解。而它恰恰是**生活层内容的主体**。你把外层的生活模式保住了，但内层分类法里，生活层的 payload 无处安放。若强行塞进“软约束”，软约束桶就退化成新的垃圾桶。

### 缺陷二：内层分类与存储策略还没挂钩

你说“三种存储策略给 Kimi 跑”，但分类和策略是两件事。三种性质必须各配一条完整的生命周期管线，否则只是换了名字的三个标签：

- **硬约束**：高写入门槛（需验证/确认）→ 强制执行 → 显式可撤销；
- **软约束**：低写入门槛 → 允许被高频违反行为覆盖 → 置信度随时间/使用衰减；
- **临时**：带 TTL → 到期自动失效 → 不进入长期检索池。

框架里有桶，没管线。

### 缺陷三：性质判定本身是个未解决的难题

“一条记忆怎么存只由它的性质决定”——**谁在什么时刻判定性质？**

- 判定发生在写入瞬间，是模型的一次推理，会出错；
- 错误代价不对称：把软偏好误判为硬约束 = 一个高置信度的错误规则被永久强制执行，**这是整个系统里最贵的单点故障**；
- 因此硬约束的授予不能是静默的：需要**显式确认机制**（“我记住：你要求所有代码必须用 TS，对吗？”）和**审计面板**（用户随时能看/改/删自己的硬约束）——目前框架完全没提；
- 还缺**性质迁移**：临时约束延期三次后自动转正为长期？软约束被违反十次后降级删除？生命周期内的性质漂移无路可走。

### 缺陷四：“模式规定边界”的语义太模糊

边界规定的到底是三件事中的哪一件？

1. **写边界**——该模式下产生的记忆只进某个池？
2. **读边界**——该模式下允许调用哪些记忆池？
3. **权限边界**——敏感信息不跨域泄露？

三者机制完全不同。而且如果按“边界”语义推到底，你会遇到一个尴尬结论：**“混合模式”不是第三种边界，而是边界的缺席**——它等于默认的跨域调用。切到工作/生活才是不设防状态外的收紧动作。所以外层其实只有两个真实状态，第三个是个伪选项（第二次提醒了，这次它在你的新语义下更显眼）。

### 缺陷五：敏感性防线依然缺席

上次指出生活区=隐私区、工作区=合规区。这次外层改成了“边界”，理论上正是承载权限轴的位置——但你没有把它落实。需要明说：**边界规定的头号职责是敏感信息不可跨界调用**（生活模式记下的健康信息，不能在工作会话里被随手调出来）。

## 四维逐项评价

| 维度 | 判定 | 评价 |
|---|---|---|
| 类型：规则 / 陈述 | ✅ 成立 | 正交、近似 MECE，对应程序性/语义记忆。**补丁**：陈述需分两个子类——静态事实（“妹妹叫小红”）与任务态/情景（“项目卡在登录模块”，带时间索引、高更新频率），二者行为差异极大 |
| 重要度：高 / 中 / 低 | ⚠️ 成立但需两处修正 | ① 必须**动态化**：写入时只是先验估计，之后由调用频率+违反代价重算，否则低重要度的“永久”记忆会无限堆积；② 重要度是**关系属性**——过敏信息写代码时无关、点餐时致命，存储时存全局先验，检索时按当前作用域重估 |

且无法表达否定与程度。改为：


  词表 W = { 词: 权重 }，权重 w_i ∈ [-1, 1]，实数
  「不喜欢」= w(不) + w(喜欢) = (-0.8) + 0.3 = -0.5，负值自动表达反转


  - 所有候选词一律保留，靠权重趋近 0 自然淘汰，不做删除
  - 优化对象是 N 维连续权重向量，不是 N 选 K 的子集
  - 每个词的权重必须可被人工查看和手动覆盖


## 规格二：词表必须至少包含五个功能组


  G1 强化词  必须/一定/永远/绝对/禁止/不得   → 正权重，抬高 I 与 V
  G2 弱化词  最好/尽量/一般/通常/可能/随便   → 负权重，压低 I
  G3 否定词  不/别/没有/从不/并非           → 负权重，实现语义反转
  G4 显式标记 记住/以后都/每次/从此/永久/别忘 → 强正权重，触发用户覆盖
  G5 主题词  领域相关名词，决定这条记忆属于哪个作用域


  必须额外实现转义处理：双重否定、疑问语气（疑问句不得判为高 V，应降为待确认）。


## 规格三：关键词出特征，不直接出结论


禁止用关键词直接赋值五维。关键词只是四路特征之一：


  I_raw = Σ(命中词权重) + 句法分 + 位置分 + LLM兜底分


  - 句法分：祈使句 > 陈述句 > 疑问句
  - 位置分：位于"纠正句"（用户否定上轮输出之后的话语）的信号权重加倍
  - LLM兜底分：见规格四
  - 最终 I = clamp(I_raw, 0.02, 0.95)


## 规格四：快慢双路径，未命中绝不允许静默通过


  快路径：命中词表中至少一个 |w| >= 0.5 的词 → 高置信，直接赋值 V >= 0.8
  慢路径：未命中任何强信号词 → 禁止跳过，必须走以下两条之一：
           (a) 调用 LLM 做语义判定；
           (b) 无条件降级为 V = 0.5，走"限定调用"闸门
  硬约束：任何输入都不得出现"无判定结果"的状态。沉默是最坏的失效模式，
          因为它必然发生在最贵的遗漏上（例如用户说"我吃花生会死"而词表只认"过敏"）。


## 规格五：标定流程


  1. 准备训练集 D_train 与评测集 D_eval，二者严格不重叠
  2. D_eval 中必须包含 ≥15% 的"训练时未出现过的表达"，用于检测词汇坍缩
  3. 初始化词权重（可用启发式初值），连入下游 u/d/r/s/c 五函数
  4. 迭代优化权重向量，每轮在 D_eval 上计算下述 J 与 EP
  5. 记录每轮的 J、EP、CR、MR 四条曲线


# 收敛判据（本系统的原生语言，禁止使用错误率口径）


严禁使用"错误率 < 1%"这类准确率指标作为停止条件。
原因：准确率把"漏掉过敏"和"多存一句噪声"视为同等错误，
与本系统的"代价不对称"公理直接冲突。


改用以下三条判据，全部满足才允许宣告收敛：


  【判据一｜干净】暴露事件 EP = 0
    EP = 跨域泄露次数 + 把存疑当确证的次数
    这两类在代价矩阵中分别为 10 分与 8 分，属一票否决。
    EP > 0 时，无论 J 降到多少，一律不得宣告收敛。


  【判据二｜收敛】边际代价改善趋零
    定义加权错配代价 J = Σ(单条错配代价) / N
    当连续 3 个标定轮次同时满足 |J_n − J_{n−1}| / J_{n−1} < 0.02 时判定收敛
    注意：目标是 J 最小，不是错判条数最少。二者的最优点不同，
          本系统取前者，且前者通常更保守。


  【判据三｜泛化】词汇坍缩受控
    失守率 MR = 未命中快路径且未触发慢路径的样本比例，必须为 0
    坍缩率 CR = D_eval 中"未见表达"子集的漏检率，须低于 D_train 漏检率的 1.5 倍
    CR 超标即判定为过拟合，须回退权重并扩充词表，而不是继续迭代


  若迭代达到 30 轮仍未同时满足三条，停止并输出诊断报告，
  禁止通过放宽判据来强行收敛。

### A类：33处“误存闲聊句”( 占失误 87%)

**出问题的组件：摄取层“创建条件”+ 慢路径，错不在 u/d/r/s/c。** 链路是：

1. 这类句(“看看报告”“做体检”“称体重”)没有任何强命中词 → **不走快路径**，进入慢路径；
2. 慢路径里 LLM 兜底给 `verdict=worth` → `V=0.6`(见 `SimLLM`,ingest_core.ps1:61),`llmSc = Gllmw(0.5)×conf(1.0,`未见句`)×Gllmf(0.4)=0.20`,加上主题词 sum(0.1~0.3) → `I_raw≈0.3~0.5`;
3. 创建条件是 `Pipe` 里那条:`$create=(($V -ge 0.5) -or $isDneg) -and ($I -ge $pv["theta"])`。**`V≥0.5` 这个分支是为“显式标记/G4 确证句”设计的入口，但它和“LLM 疑似句”撞车了** —— 疑似句 V=0.5~0.6 同样满足，而 `theta=0.15`(在14句摄取集上，非创建句全靠否定/疑问/转义把 I 压到<0.15,所以网格搜索才能选中这么低的下限)。
4. 262轮真实对话里出现了第三种句型：**中性陈述句**(既无否定也无强调)，词表对它没有任何抑制通道，全靠 LLM 兜底 → 33处全灭。

**精准修改点(2处，都在摄取层)：**
- 创建双门槛：库内还剩 `theta=0.15` 只作**待确认队列**门槛；直存需 `(V≥0.8 或 fast句) AND I≥θ*(⦈0.5)`;
- 疑似句罚重：慢路径 `llmSc` 中把“worth 但非确证”的 conf 贡献再乘 Gllmf 一次('疑似双层衰减')，即疑似句最多 I≈0.1,永远够不着直存线。

### B类：5处“撤销后仍引用 any”(占失误13%)

**出问题的组件：摄取层的“重复出现=强化”假设 + c函数缺失。** 链路是：

1. 第152轮撤销 any(`R:` 分支:`revoked=true`),这是 d 函数三死里的“撤销亡” ✓ 正确；
2. 但第154轮 “any 特例收口，下版本移除|#any” —— 词表命中 any → sum>0 → 照常进管道；因 id 已存在，走“**重复出现被强化**”分支(`S+0.15 / I+0.05`),把一个已死的条目**又养肥了**；
3. v2 规约里“时长只接受用户信号”的前提是**提及=证实**。但这句话是*引用/预告式提及*，语义上和“我再重申一遍禁令”完全相反 —— 词表的 G3 否定组只作用于句子内部，管不到“这句话与已有条目的关系”；
4. c函数(确认程序)本来该在这一步出场：**动一条已有规则前先问**。模拟里 c 未实现，所以这5处 E 引用才畅通。

**精准修改点(1处)：**
- 重复出现前加**意图仲裁**:`if($e.revoked -and $命中包含该id)` → 强制走 c 程序(问一句“这条 any 规则是恢复还是维持撤销？”),回答落定前**不得走强化分支**，一票保护已撤销条目。

### 附带发现：生活层 0 误差里藏着一个临界值
